# 剪映专业版母版与可编辑草稿执行规则

## 平台差异（macOS）

> 本节为 macOS 适配注记，具体入口位置以本机剪映专业版实际界面为准；首次执行时逐项核对并更新本节。

- 剪映 macOS 版同样提供智能字幕/识别字幕、云空间/云草稿上传等能力，但菜单位置与 Windows 版不同；找不到同名入口时在顶部菜单（文件/编辑/导出）与设置中查找等价项。
- macOS 草稿默认位于 `~/Movies/JianyingPro/User Data/Projects/com.lveditor.draft/`（以本机实际为准）；备份前先确认剪映已保存且未占用草稿。
- macOS 没有盘符，所有备份路径使用 `<工作区>` 参数（默认 `~/VLOG剪辑工作区`）。
- 云同步要求桌面端与手机端登录同一账号；同步状态以桌面端明确提示为准。

## 草稿安全

1. 确认剪映未占用要复制的草稿文件后再备份；如正在运行，优先只读检查或先触发保存。
2. 备份整个本期草稿目录，名称附加时间戳和里程碑。
3. 不直接手工改写未知版本的剪映 JSON，不向草稿 JSON 写 BGM 音量关键帧。
4. 每次重大操作后确认自动保存时间更新，并保留用户已有的无关改动。
5. 不把导出的 MP4 当作可编辑草稿。交付草稿必须保留片段边界、文本对象、音频轨、关键帧、转场和特效对象。

## 时间线搭建

- 按已选镜头链搭建主视频轨，先锁定 beat 和章节边界，再做逐帧精修。
- 根据实际使用区间复核每段的起点/终点状态，不用整条文件头尾代替源区间状态。
- 使用 J/L cut 保留人物原声或环境声，减少生硬切断。
- 普通动作连续性优先硬切或匹配剪辑；转场只用于真实章节和地点变化。
- 每个确认的地点切换必须按选片日志使用一个过场或明确硬切。
- 横屏素材进入 9:16 项目时使用关键帧跟随主体、智能裁切或背景延展，不拉伸变形。
- 人物原声、环境声和旁白分别放置并清晰命名轨道；制作无 BGM 母版时暂不放最终 BGM，交付草稿阶段再放回独立可编辑 BGM 轨。

## 音乐节拍与画面切点

全自动 BGM 模式在进入最终精修前已经选定曲目并生成节拍侧文件：

- 读取节拍时间点，把每个相邻视频片段边界吸附到附近清晰节拍。
- 只处理视频片段切换，不追加动作、字幕、特效或音效逐拍同步要求。
- 不为踩点切断一句完整的话或关键互动；内容完整后使用最近节拍。
- 无 BGM 母版阶段不需要导入 BGM。节拍只作为画面边界参考，最终自动混音由 `mix-bgm.py` 完成；交付草稿阶段仍需在剪映界面中加入可编辑 BGM 轨。

半自动模式在用户后来提供音乐时，不重新选故事或镜头，只按新节拍微调边界并重新导出母版。用户明确接受不重导时可以只做后混音，但该分支不承诺画面切换踩点。

## 字幕与声音

- 制作字幕前必须读取 [subtitle-system.md](subtitle-system.md)。只维护一份字幕脚本，并把每条标记为 `main`、`scene`、`chapter` 或 `end_card`；对白、叙事和重点仅用于内部判断，不再分别设计视觉。`end_card` 固定为电视关机后的彩色“晚安”。
- 人物原声字幕默认必须自动生成，不能只保留场景标题或编辑说明。画面、变速、片段顺序和原声锁定后，先暂时关闭 BGM、歌曲人声和干扰音效，再在剪映对当前时间线执行“智能字幕/识别字幕”，识别范围只选择视频原声和需要转写的旁白。全选识别结果，一次性套用固定主字幕预设；只快速修正明显错字、人名、地点、数字和断句，删除听不清、明显误识别及无信息口头词。剪映识别不可用或主要对白明显无法使用时才运行本地转写并导入 SRT。两种方式都失败时暂停并明确报告，不能默默交付无对白字幕的版本。
- 人物对白与必要的行动说明统一使用下方主字幕样式。开场和重要换场才使用章节或场景标题；约 100 秒成片默认 1 个开场标题、2–5 个场景标题。
- 直接套用固定预设，不逐条选择字体、颜色、花字和特效。普通主字幕不逐词变色、不弹跳、不滑入；章节标题只允许一次短淡入或轻弹入。
- 抽检开头、中段、结尾，并完整播放检查错字、遮脸、重叠和阅读时间；以本能观看是否舒服为最终标准。
- 所有已用视频片段先保留正常原声音量，不批量压低整段素材；只有确认属于纯景色/蒙太奇且现场声无叙事价值时，才允许降低该区间环境声。
- 按成片时间码把声音标为 `dialogue`、`key_interaction`、`ambience` 或 `scenery_montage`，写入 `05_音乐音效/声音区间.csv`。同一视频片段可拆成多个区间，不能用整条片段的单一音量代替区间判断。
- 先把视频原声和旁白调整到自然、清楚；人物说话和关键互动不得被其他原声轨盖住。
- 检查每条音频轨左侧扬声器状态，防止整轨误静音。
- 给剪辑脚本和声音区间表保留人物说话、关键互动、环境声和纯景色蒙太奇区间，供后混音直接控制 BGM。
- 剪映导出页的“音频导出”通常表示额外导出独立音频文件，不等于视频是否包含声音；仍以母版音频流和实际试听为准。

## 轻网感特效与音效

- 锁定镜头、原声和字幕后读取 [effects-and-sfx.md](effects-and-sfx.md)，逐 beat 分别填写 `picture_effect`、`person_effect`、`sfx` 和一句 `effect_reason`；默认全部为 `none`，不建立评分。
- 先判断整体画面还是人物需要强化。同一瞬间画面特效和人物特效二选一；确有帮助时最多再放一个轻音效，不能默认三者叠加。
- 把画面和人物特效应用在视频层，固定字幕保持在上层，不随主体移动，也不因特效重新构图。跟踪、抠像或描边不稳时直接取消该效果。
- 场景特效不能代替真实过场或硬切。先执行选片日志中的过场/硬切，再决定是否添加白名单中的轻效果。
- 新增音效放在独立命名轨道，只使用剪映内可合法使用的音效或用户提供的本地合法文件。优先保留人物原声和真实动作声；对白听不清时先降低或删除音效。
- 特效和音效不强制踩 BGM。音效只对齐真实动作、结果或场景切换；画面已经成立或情绪不匹配时保持 `none`。
- 完整播放时分别抽查对白、关键互动、换场、蒙太奇和收尾；除固定 `tv_shutdown`＋“晚安”片尾外，如果关闭新增特效后更自然，就交付无该特效的版本。

### 固定电视关机＋“晚安”片尾

1. 先为固定片尾预留约 1 秒结束卡时间，使完整片尾计入目标总时长，不在成片锁定后无条件向后延长。
2. 在最后一个真实故事画面结束时应用 `tv_shutdown`。优先使用剪映内含义相同的电视关机效果；不存在时用视频层关键帧/蒙版模拟“画面压成横向亮线 → 收成亮点 → 纯黑”。
3. 关机完成后在纯黑画面中央放置独立 `end_card` 文本“晚安”，使用 [subtitle-system.md](subtitle-system.md) 的彩色可爱字体与固定中心坐标。
4. 不强制添加关机音效。关闭任何突兀或盖住原声的效果自带声音；BGM 在片尾自然淡出并与最终画面同时结束。
5. 把 `tv_shutdown` 与“晚安”文本作为独立可编辑对象保留在交付草稿中；手机版缺少同名效果或字体时，在交付说明中记录替代项，不得直接删除固定片尾。

## 导出无 BGM 母版

- 默认 MP4、H.264、目标分辨率、30 fps、推荐码率、AAC 48 kHz。
- 导出到 `99_临时/<项目名>_无BGM母版_vNN.mp4`，使用递增版本号，不覆盖旧版本。
- 母版总时长必须由故事视频决定，不含音乐尾巴。
- 导出后检查视频流、音频流、人物声音、黑帧、错字和音画同步。
- 检查最后一个真实画面确实执行电视关机效果，关机后纯黑中央出现彩色可爱字体“晚安”，且片尾没有意外黑屏拖尾。
- 不看字幕试听所有人物说话和关键互动；如果母版阶段已经听不清，先修复原声再进入 BGM 混音。
- 剪映草稿和无 BGM 母版不是最终配乐成片；最终文件由 [bgm-auto.md](bgm-auto.md) 的后混音流程生成。

## 可编辑草稿与手机续剪

1. 从已经审定的最终时间线复制一个新草稿，命名为 `<项目名>_editable_vNN`；不在唯一工作草稿上做交付打包。
2. 保留每个视频片段的独立边界与源区间；字幕及“晚安”结束卡保持独立文本对象；人物原声、环境声、旁白、音效和 BGM 分轨；转场、滤镜、调色、贴纸、画面特效、人物特效和 `tv_shutdown` 保持可选择、可删除、可调整。
3. 有 BGM 时，通过剪映界面导入或选择同一首音乐，还原最终成片使用的入点、裁切、淡入淡出和人声退位区间。允许最终 MP4 继续使用外部 sidechain 混音，但交付草稿必须至少能独立调整 BGM，不得只放一条已经混平的总音轨。
4. 保存并确认自动保存时间更新后，关闭或释放草稿占用，再把完整草稿目录备份到 `<工作区>/可编辑作品/<项目名>_editable_<YYYYMMDD_HHMMSS>/剪映草稿/`。新建时间戳版本，不覆盖旧备份。
5. 若草稿引用的本地视频、图片、音频或字体不包含在草稿目录中，把实际使用的关联文件复制到同一交付目录的 `关联素材\`，并保留原文件名。不要移动或删除原素材。
6. 在交付目录创建 `草稿交付说明.md`，记录草稿名称、剪映版本、备份时间、BGM 名称、使用的音效和特效、云同步状态、已知跨端缺失项，以及本地恢复所需的草稿和关联素材位置。
7. 该步骤在项目首次交付前向用户确认一次“上传云草稿”；确认后同项目自动执行，不重复询问：使用与手机版相同的剪映账号，在剪映专业版中直接触发“上传到我的云空间/云草稿”或当前版本提供的草稿云同步入口；持续等待上传完成，并确认桌面端明确显示同步成功或已上传。
8. 手机版通过同一账号的云空间打开草稿，不从工作区路径直接打开。若条件允许，确认手机端草稿列表可见后再报告“手机续剪已就绪”；只完成本地复制时报告“本地草稿已备份，手机云同步待完成”。
9. 跨端打开后，如字体、版权音乐、会员效果、第三方字体或桌面端专属能力需要重新下载或不可用，在交付说明中如实记录；不把平台兼容限制误报为草稿损坏。

本地备份与云同步必须同时保留：本地备份用于恢复和版本留档，云空间草稿用于手机版继续编辑。云同步失败不阻止成片和本地草稿交付，但不得声称手机端已经可编辑。

只有扫码登录、账号安全验证、付费扩容或其他必须由账号持有人确认的操作才允许请求用户介入；用户处理后从上传步骤继续，不重复剪辑流程。未尝试上传、上传仍在进行或同步状态未知时，不得报告“云草稿已交付”。

## 最终交付

有匹配 BGM 时，对无 BGM 母版运行自动混音并检查最终 `final.mp4`。没有匹配音乐时，把无 BGM 母版作为有效的 `final_无BGM.mp4` 交付，不阻塞项目。无论有无 BGM，都必须同时完成本地可编辑草稿备份；手机续剪状态单独报告。

完整播放的对象必须是最终交付文件，而不是只播放剪映预览或无 BGM 母版。
