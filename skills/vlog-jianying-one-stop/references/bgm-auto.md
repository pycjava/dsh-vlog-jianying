## 不可违反规则

- AI 不下载任何有版权的音乐，只使用用户本地文件或用户在平台内自行选择的音乐。
- 不向未知版本的剪映草稿 JSON 写入 BGM、音量或关键帧。
- 剪映负责画面、原声、旁白和字幕；最终 BGM 由 FFmpeg 与无 BGM 母版混合。
- 人物说话、笑声和关键互动必须轻松听清；自动闪避不能替代试听。
- 先保留正常人物原声，再识别声音区间，最后调整 BGM。不得先把整段素材原声压低，再期待 sidechain 找回人声。
- 只在人物说话和关键互动区间降低 BGM；只有确认没有有效人物信息的纯景色或蒙太奇区间才提高 BGM。
- 踩点只约束相邻视频片段的切换，不要求片段内部动作、字幕、特效或音效逐拍同步。
- 无匹配音乐时无 BGM 版本仍是有效交付，不阻塞项目。

## 本地曲库

`MusicLibraryPath` 默认指向项目 `05_音乐音效/library/`，也可以使用用户指定的任意已有目录。不得强制用户移动或重命名音乐原件。

支持脚本可读取的常见音频格式：`.mp3`、`.wav`、`.m4a`、`.aac`、`.flac`、`.ogg`。

## 索引与节拍侧文件

运行：

```bash
python3 <SKILL_DIR>/scripts/build-music-index.py <MusicLibraryPath> --output <项目目录/05_音乐音效/music-index.csv>
```

索引字段：

```text
file,duration,bpm,energy_peak_time,has_vocals,mood_tags,
beat_times_file,last_used,use_count,analysis_status
```

脚本使用 ffprobe 获取时长；librosa 可用时分析 BPM、能量峰值和真实节拍时间点，并把节拍写入同目录的 JSON 侧文件。librosa 缺失或分析失败时进入降级模式，相关字段留空，但仍输出索引。

`has_vocals` 不得仅凭 RMS 或节拍推断。优先从文件名标签或已有索引保留；无法判断时写 `unknown`。`mood_tags` 优先保留用户已有标注，再尝试从有限关键词解析；解析不到时留空。

脚本重复运行必须保留用户填写的 `mood_tags`、`has_vocals`、`last_used` 和 `use_count`，不得修改音乐原件。

## 模式判定

### 全自动

同时满足：

- 曲库存在至少一首情绪可匹配的音乐。
- 计算入点后，音乐剩余可用时长可以覆盖成片。
- 用户没有要求留给平台曲库。
- 能取得真实节拍侧文件，或者用户明确接受只做混音、不保证画面踩点。

### 半自动

出现任一情况：

- 曲库为空。
- 曲目没有可用情绪标签或都不匹配。
- 从计划入点开始的剩余时长不足。
- 用户要求在剪映/平台曲库中自行选择。
- 需要片段切换踩点，但本地音乐尚未提供或没有节拍数据。

半自动不是失败。先完成故事、画面、原声、旁白和字幕，并交付无 BGM 成片。

## 全自动模式

### 选曲

1. 用整条 beat 情绪弧线匹配 `mood_tags`，用户明确指定曲目时优先。
2. 计算计划入点：

```text
start = max(0, energy_peak_time - hook_duration)
```

3. 使用 `duration - start >= target_duration` 判断真实可用时长，不只比较音乐总时长。
4. 同分时优先 `use_count` 更低、最近没有使用的音乐。

没有能量数据时 `start = 0`。不得为了能量高潮切断钩子的原声爆点。

### 先取得音乐，再锁定画面切点

最终精修前读取 `beat_times_file`：

1. 保留故事镜头、观点和互动的入选结果。
2. 把每个相邻视频片段边界移动到附近节拍。
3. 只做小范围入点/出点调整，不重新改变故事和 beat。
4. 若最近节拍会切断一句话或完整互动，使用内容结束后的最近节拍。
5. 然后在剪映导出无 BGM 母版。

## 半自动模式

先把无 BGM 成片交付为：

```text
07_交付/<项目名>_final_无BGM.mp4
```

回复中只说明：本片情绪、建议 BPM、音乐目录和两种继续方式。

推荐路径：用户把一首本地音乐放入 `MusicLibraryPath` 并回复“继续”。随后：

```text
重建索引 → 读取节拍 → 不重选镜头 → 自动微调片段边界
→ 重新导出无 BGM 母版 → 自动混音 → 审片 → final.mp4
```

如果用户明确要求“不重新导出画面”，直接后混音，但必须说明该分支不保证视频片段切换踩点。

用户在剪映中手动加入平台音乐属于外部路径，无法自动执行 FFmpeg 闪避。用户仍要求 Skill 完成交付时，必须重新导出并试听人物声音，不能默认手动音乐已经合格。

建议提示模板：

```text
无 BGM 成片已交付：<路径>（<时长> 秒）
本片情绪：<描述>；建议 BPM：<区间>。
当前本地曲库没有匹配音乐，这不影响本次交付。

如需自动配乐：把一首音乐放入 <MusicLibraryPath>，回复“继续”。
我会读取节拍、只微调切点并自动混音，不重新选择故事或镜头。
```

## 自动混音

先按最终时间线生成 `05_音乐音效/声音区间.csv`：

```csv
start,end,sound_role,note
0.00,4.20,dialogue,开场人物说话
18.40,21.10,key_interaction,递东西与双方反应
42.00,48.50,scenery_montage,机场与窗外景色
```

`sound_role` 只使用：

- `dialogue`：人物有信息的说话。
- `key_interaction`：笑声、惊呼、问答、递物、展示结果等关键互动。
- `ambience`：需要保留的现场氛围，没有人物信息。
- `scenery_montage`：确认没有有效人物说话或关键互动的纯景色与蒙太奇。

时间码按成片时间线填写，不按源文件时长填写。同一视频片段可以被拆成多个声音角色。没有被标记的区间按 `ambience` 处理，不自动当成纯音乐段。

运行：

```bash
python3 <SKILL_DIR>/scripts/mix-bgm.py \
  --video-path <无BGM母版> \
  --bgm-path <音乐文件> \
  --output-path <07_交付/项目名_final.mp4> \
  --start-seconds <音乐入点> \
  --sound-intervals-csv <05_音乐音效/声音区间.csv>
```

默认流程：

1. ffprobe 取得母版和音乐时长。
2. 从 `StartSeconds` 截取与视频等长的音乐；剩余时长不足时明确失败，不生成半截音乐成片。
3. 无 BGM 母版中的人物原声默认保持正常音量，不对整段素材统一衰减。
4. BGM 默认中等音量为线性 `0.35`；`dialogue` 和 `key_interaction` 区间降为 `0.10`，`scenery_montage` 区间可升为 `0.45`，`ambience` 保持默认值。
5. 区间边缘使用短过渡，避免 BGM 音量突跳；声音角色冲突时人物说话/关键互动优先。
6. BGM 在视频结尾前 1.8 秒淡出。
7. 原视频流直接复制，最终音频编码为 AAC 48 kHz。
8. 输出使用临时文件原子替换，避免失败时留下假成片。

声音区间表是默认主控。只有无法可靠建立区间表时，才允许不传 `SoundIntervalsCsv` 并退回自动 sidechain；这属于降级模式。Sidechain 会同时响应风噪、交通声和其他大声音，不能区分“人物在说话”和“环境很响”，因此不得把它当作语义区间的等价替代。

## 验收

- 运行 `verify-export.py`，确认视频流、音频流、时长、画幅和帧率。
- 音乐不得晚于最后一帧，不能产生黑屏或音乐尾巴。
- 试听钩子、观点对话、趣味互动、持续环境声和纯音乐段。
- 先单独试听无 BGM 母版，确认人物原声没有在上游被错误压低或静音；有问题先修母版，不能只靠降低 BGM 补救。
- 人物需要猜词或回放才能听清时继续降低 BGM。
- 关闭字幕再试听所有 `dialogue` 和 `key_interaction` 区间；任何一句需要猜词或回放都不通过。
- 抽查所有 `scenery_montage` 区间，确认其中确实没有应保留的人物信息。
- BGM 在区间边缘有突跳时调整区间边界或过渡时间；降级 sidechain 模式出现抽吸、持续消失或突然窜起时再调整 sidechain 参数。
- 完整播放最终 `final.mp4`，不能只验收无 BGM 母版。

## 月度选曲清单

只有用户明确请求“推荐本月热门音乐”时才联网查询，不在普通剪辑任务中自动联网。输出约 15 首：

```text
歌名 | 歌手 | 风格标签 | BPM 区间 | 适配情绪 | 推荐理由 | 建议高潮位置
```

用户自行取得合法音频并放入本地目录；推荐清单不代表 Skill 可以下载或复制受版权保护的音乐。
