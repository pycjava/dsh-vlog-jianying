# Vlog 剪映 L3 V3 一站式制作

## 目标

把用户的一段自然语言连续转化为：

```text
创作意图 → beat 故事 → 傻瓜式拍摄脚本 → 事实时间线 → 宽容匹配
→ 链式选片与过场 → 剪映无 BGM 母版 → 自动/半自动配乐 → 本能审片 → 成片＋可编辑草稿
```

默认完成抖音/小红书竖屏 Vlog。优先保证“用户照着脚本拍，剪出来仍是最初想表达的那条视频”，不要把流程变成摄影考试或面向用户的量化验收。

## 核心概念

**时间逻辑**：素材在物理世界中的实际先后顺序。优先用媒体 `creation_time` 重建“事实时间线”，缺失时用文件 mtime 作为低可信参考。高可信时间用于阻止观众可感知的时间穿帮；mtime 不得单独硬否决用户明确的故事顺序或画面上成立的状态衔接。

**叙事逻辑**：由 beat 方案决定故事为什么从这一镜进入下一镜。叙事可以打乱物理时间，但相邻镜头应满足状态衔接，例如“出门 → 在路上 → 到达 → 做事 → 结果”。`beat_00` 和显式声明的非线性 beat 可以跳出时间顺序。

两者关系：叙事逻辑决定 beat 宏观顺序；高可信时间、地点、明暗和片段起止状态约束微观衔接。用户明确顺序和 `must_include` 高于自动时间推断。

## 核心原则

1. 把拍摄合同定义为语义合同。单镜头只要求：所属故事段、重要性、远/中/近景、画面在做什么、可选角度。
2. 把景别、角度和普通画质当作选片提示，不当作拒绝素材的门槛。只要画面行为能承担故事任务，就允许替代。
3. 只在文件不可读，或不可替代 beat 完全没有可用画面时要求补拍。普通缺口自动替代、合并或略过。
4. 每个真实场景切换必须判断一次“过场或硬切”。有合适的移动/出发/到达素材时选择一个最简洁的过场；没有时硬切，不用黑场或虚构画面补洞。
5. 每个 beat 只有一个声音主角。先按正常音量保留人物原声，再识别人物说话和关键互动区间；只在这些区间降低 BGM，只有确认没有有效人物声音的纯景色或蒙太奇区间才提高 BGM。不得先压低整段素材原声再依赖自动闪避；字幕不能补救听不清的人声。所有实际可听清的人物原声默认通过剪映“智能字幕/识别字幕”生成时间码准确、可编辑的主字幕；本地转写仅作失败备用，不等待用户手打或逐条确认。
6. 对白、叙事和重点只作为内部内容判断，不再各做一套视觉。正文输出只有两种：下方固定白字黑边的主字幕，以及开场或重要换场使用的章节/场景标题；所有成片另有一个电视关机后的固定 `end_card`“晚安”。主字幕、场景时间、场景句、开场两行标题和结束卡必须套用 [subtitle-system.md](references/subtitle-system.md) 的固定坐标；轻微遮挡人物、手部或画面内容也不得移动字幕，不得为避让字幕改变裁切、缩放或画面构图。“晚安”使用彩色可爱字体，是唯一不采用普通白字黑边样式的固定例外。
7. 默认采用轻网感，但正文画面特效、人物特效和音效都不是必做项。情绪不匹配时必须不用；同一瞬间画面与人物特效二选一，最多再配一个不遮盖原声的轻音效。唯一强制特效是所有成片末尾的 `tv_shutdown`，完成后显示“晚安”结束卡。完整规则读取 [effects-and-sfx.md](references/effects-and-sfx.md)。
8. 最终质量靠完整播放和本能判断。内部接点评分只用于选片和复查，不作为素材拒绝或面向用户的评分表。
9. 最多暂停一次常规确认。计划拍摄模式在开拍前确认；已有素材模式只在没有故事线时让用户选择一次提案。
10. 保护原素材、音乐原件和已有草稿改动，不移动、不覆盖、不删除、不改名。改动草稿前先备份。
11. 不直接改写未知版本的剪映草稿 JSON，也不向剪映 JSON 写 BGM 音量关键帧。
12. 每个成片必须同时交付可编辑剪映草稿。草稿保留独立视频片段、字幕、原声、旁白、BGM、音效和特效，不用扁平化成片替代时间线；本地备份固定放入 `<工作区>/可编辑作品`。剪辑完成后默认直接把交付草稿上传到当前剪映账号的云空间/云草稿并等待同步完成，不要求用户再次提醒；手机续剪使用同一账号的云草稿。

## 选择模式

### 模式 A：先规划后拍

1. 生成创作简报、`beat_00` 和 6–9 个正文 beat，使拍摄方案与约 100 秒的成片节奏匹配。
2. 把每个 beat 转成低门槛拍摄清单；地点变化处增加一条“随手拍即可”的过场必拍项。
3. 按实际地点重排为拍摄顺序，同时保留每个镜头对应的故事段。
4. 提交一次完整拍摄方案。确认后不再询问常规摄影或剪辑选择。
5. 用户拍完并提供原素材后，从素材接收阶段自动继续。

制作拍摄脚本时必须读取 [l3-planning.md](references/l3-planning.md)。

### 模式 B：已有素材后剪

- 有明确故事线：直接建立 beat 并连续执行，不再确认。
- 只有主题或没有故事线：分析素材后给出 2–3 个能实现的故事提案，让用户选择一次，随后连续执行。

允许自动替代、合并或删除非关键 beat，并在完成回复中报告明显改变。

## 默认规格

- 平台：抖音。
- 画幅：竖屏 `9:16`。
- 时长：默认目标 100 秒左右，优先落在 90–110 秒；用户有明确目标时长时以用户为准。除非用户特别要求短视频，不因旧的 60 秒默认值压缩故事。
- 输出：1080×1920、30 fps、MP4、H.264、AAC 48 kHz、Rec.709 SDR。
- 风格：生活记录、真实情绪、快慢交替，故事优先于炫技。
- 音乐目录：项目 `05_音乐音效/library/`；用户可以指定已有本地目录。
- 工作区根目录：默认 `~/VLOG剪辑工作区`（Windows 上游默认为 `E:\codex\VLOG剪辑工作区`）；用户可指定任意已有目录，全程不强制移动素材。
- 可编辑草稿目录：`<工作区>/可编辑作品/<项目名>_editable_<YYYYMMDD_HHMMSS>/`，每次新建版本，不覆盖旧草稿。

脚本约定：以下命令中的 `<SKILL_DIR>` 指本技能所在目录（含 SKILL.md 的目录），执行时替换为实际绝对路径，不假定当前工作目录。全部脚本统一使用 `python3` 调用，退出码 0 为成功、2 为环境/输入错误（stderr 含可读原因）。

用户明确要求覆盖默认值，但版权、安全、原素材保护和人声清楚规则不被覆盖。

## 阶段 0：环境与工作区检查

进入素材处理（阶段 2）之前先运行：

```bash
python3 <SKILL_DIR>/scripts/check-env.py
```

- 缺少 ffmpeg/ffprobe 时明确告知安装方式（macOS: `brew install ffmpeg`），不进入依赖它们的阶段。
- faster-whisper、librosa 缺失只是功能降级（本地转写、节拍分析不可用），照常继续，并在完成回复中注明。
- 与用户确认或按默认值确定 `<工作区>` 根目录；不存在则创建，不移动用户已有文件。

## 阶段 1：生成拍摄方案

1. 提取主题、人物、地点、事件、情绪落点、必须出现内容、平台和时长。
2. 对不影响方向的缺项直接采用默认值，不逐项追问。
3. 创建 `beat_00` 和 6–9 个正文 beat，使叙事能自然覆盖约 100 秒；每个 beat 只定义目的、预计时长、情绪、节奏、声音主角、需要出现的行为，以及是否允许非线性时间。
4. 为每个 beat 生成最少够剪的远/中/近景组合，不强迫三种景别齐全。
5. 每次地点变化增加一条低门槛过场必拍项。
6. 使用 [confirmation-template.md](references/confirmation-template.md) 提交一次确认；用户要求直接出脚本时跳过确认。

不要主动加入焦段、机位高度、拍摄距离、曝光、对焦参数、器材、精确秒数、动作预留或拍摄遍数。

先运行：

```bash
python3 <SKILL_DIR>/scripts/build-real-timeline.py --source-dir <素材目录> --output-csv <项目目录/01_项目资料/00b_事实时间线.csv>
```

需要看懂内容时运行：

```bash
python3 <SKILL_DIR>/scripts/prepare-review-frames.py --source-dir <素材目录> --output-dir <项目目录/99_临时/素材预览>
```

逐个查看预览帧；必要时检查原视频、音频或转写。不得根据文件名猜画面。把超过阈值的时间间隔只当作场景边界候选，必须结合 beat 地点或画面语义确认，不能仅凭十分钟间隔强插过场。

## 阶段 3：宽容匹配、链式选片与过场

必须读取 [coverage-and-matching.md](references/coverage-and-matching.md) 和 [editing-defaults.md](references/editing-defaults.md)。

1. 按“画面行为 > 人物/地点语义 > 故事段 > 景别 > 角度”匹配素材。
2. 为候选片段标记实际使用区间的起点状态和终点状态：地点、人物动作、移动/静止。
3. 统一标记高光：`highlight_status = no | candidate | keep`，并记录一个 `highlight_type` 和一句 `highlight_reason`。完整观点、完整趣味互动/反应、结果或反差、真实强情绪才能进入 `candidate`；单纯画面漂亮或适合踩点不算高光。
4. 每个 beat 有合格候选时默认只把 1 个升为 `keep`，没有合格候选可以为 0；只有第二个候选带来新的信息、反应或结果且总时长允许时，才额外保留。其余候选只作备选，不因“也是高光”强塞进成片。全片最强的 1 个高光可在 `beat_00` 短暂前置。
5. 每个 beat 保留至多 3 个普通候选；`must_include`、完整人物互动和过场素材不占普通名额，但仍受总时长和重复信息约束。
6. 先给每个 beat 锁定核心镜头，再用接点评分和宽度 3 的小范围搜索生成候选链。评分只辅助判断，不取代故事判断。
7. 用户明确顺序最高；高可信 `creation_time` 倒流在普通线性段硬否决；mtime 倒流只软扣分；`beat_00` 与声明的非线性 beat 豁免。
8. 每个确认的地点切换从独立过场池选择至多一个 0.6–1.5 秒片段。过场只需看得出移动或去向，不因抖动、构图普通而拒绝；必要时允许 2–4 倍速。
9. 没有过场就硬切。仅当新地点不易看懂时在下一场首镜加地点短字幕；不使用黑场，不拿没有移动语义的主镜头余料假装过场。
10. 在 `06_审核/选片日志.md` 记录高光标记、接点类型、分数和硬切理由，不向用户展示复杂评分表。

只有整个不可替代 beat 完全缺失时才提交短补拍清单并暂停。

## 阶段 4：音乐模式与画面切点

必须读取 [bgm-auto.md](references/bgm-auto.md)。AI 不下载有版权的音乐，只使用用户本地曲库或用户在平台内自行选择的音乐。

先运行本地曲库索引：

```bash
python3 <SKILL_DIR>/scripts/build-music-index.py <MusicLibraryPath> --output <项目目录/05_音乐音效/music-index.csv>
```

### 全自动模式

当曲库有情绪匹配且可覆盖成片的曲目时，在最终锁定画面切点前完成选曲并读取节拍侧文件。只把相邻视频片段的切换点吸附到附近清晰节拍；不要求片段内部动作、字幕、特效或音效逐拍同步。内容完整性高于踩点。

### 半自动或无 BGM 模式

曲库为空、没有匹配曲目、可用时长不足，或用户要求留给平台曲库时，先完成并交付无 BGM 成片，不阻塞项目。用户后来把一首本地音乐放入曲库并回复“继续”时，不重新选故事或镜头，只自动微调片段切点、重新导出无 BGM 母版并混音。用户坚持不重导画面时，明确该分支不保证视频切换踩点。

## 阶段 5：项目资产与剪映无 BGM 母版

在 `03_项目/YYYYMMDD_项目名_平台_画幅/` 下生成：

```text
03_文案脚本/04_剪辑脚本_带素材文件名.md
03_文案脚本/05_素材匹配与补拍.md
02_剪辑工程/
04_字幕/01_字幕脚本.md
04_字幕/02_剪映可编辑字幕.srt（可导出时备份）
04_字幕/00_本地转写初稿.srt（仅备用分支）
04_字幕/00_本地转写诊断.json（仅备用分支）

07_交付/

```

剪辑脚本逐条包含：时间码、素材文件名、源片段范围、beat、画面行为、起止状态、高光状态/类型/理由、接点类型、接点分、声音角色、原声/旁白、字幕、画面特效、人物特效、音效、特效理由、音乐节拍提示、转场和备注。声音角色只用 `dialogue`、`key_interaction`、`ambience`、`scenery_montage` 四类；特效字段只使用 [effects-and-sfx.md](references/effects-and-sfx.md) 的白名单值。

按 [jianying-execution.md](references/jianying-execution.md) 建立画面、原声、旁白和字幕。画面链、变速、片段顺序和原声锁定后，暂时关闭 BGM、歌曲人声和会干扰识别的音效，在剪映中执行“文本 → 智能字幕/识别字幕”，识别范围只选择当前时间线中的视频原声与需要转写的旁白。智能字幕直接保留为剪映中的独立可编辑文字对象；全选识别结果，一次性套用 [subtitle-system.md](references/subtitle-system.md) 的固定主字幕预设，不逐条设计样式。

智能字幕生成后只做一次本能检查：修正明显的人名、地点、数字、错字和断句，删除“嗯、啊”等无信息口头词以及明显听错的句子。自动对白与编辑说明冲突时保留对白，缩短或删除编辑说明；不移动固定字幕锚点。可以导出 SRT 时，把最终对白备份为 `04_字幕/02_剪映可编辑字幕.srt`，但不得为了生成外部文件延长流程或阻塞交付。

只有剪映智能字幕不可用、识别失败，或主要对白明显无法使用时，才运行本地备用转写：

```bash
python3 <SKILL_DIR>/scripts/transcribe-dialogue.py <无BGM原声母版> <项目目录/04_字幕/00_本地转写初稿.srt> <项目目录/04_字幕/00_本地转写诊断.json> <项目目录/99_临时/asr-model> --model small
```

备用转写只保留可听清、有效的对白，并导入剪映成为独立文字对象；不要求用户提供台词或逐条确认。低置信度、听不清或无信息量的内容直接省略，绝不猜写。剪映智能字幕和本地备用转写都失败时明确报告阻塞，不能悄悄交付没有人物对白字幕的版本。

制作字幕时必须读取 [subtitle-system.md](references/subtitle-system.md)，在一份字幕脚本中标记 `main`、`scene`、`chapter` 或 `end_card`，随后套用固定对标预设；不要逐条重新决定字体、颜色、位置、花字和特效。把所有字幕锚点视为硬约束：不做人物避让、不跟随主体移动、不通过重新构图给字幕腾位置。锁定字幕和声音后必须读取 [effects-and-sfx.md](references/effects-and-sfx.md)，分别判断画面特效、人物特效和音效，正文默认均为 `none`；最后一个真实画面结束时必须执行 `tv_shutdown`，关机完成后的黑屏中央显示固定彩色可爱字体“晚安”。特效置于字幕层下方，音效不得盖住人物原声。片尾计入目标总时长。备份已有草稿，导出 `99_临时/<项目名>_无BGM母版.mp4`。无 BGM 母版包含原声、旁白和已审定音效，用于自动混音；最终还要复制一个交付草稿并在其中放回独立可编辑 BGM 轨。

## 阶段 6：自动混音、本能审片与交付

全自动模式运行：

```bash
python3 <SKILL_DIR>/scripts/mix-bgm.py --video-path <无BGM母版> --bgm-path <本地音乐> --output-path <07_交付/项目名_final.mp4> --start-seconds <音乐入点> --sound-intervals-csv <05_音乐音效/声音区间.csv>
```

混音前先生成 `05_音乐音效/声音区间.csv`，至少包含 `start,end,sound_role,note`。无 BGM 母版中的人物原声默认保持正常音量；`dialogue` 和 `key_interaction` 区间降低 BGM，`ambience` 保持中等底乐，只有 `scenery_montage` 才提高 BGM。自动 sidechain 只在没有可靠声音区间表时作为降级方案，不能作为先压低人物原声的补救。BGM 必须随视频结束自然淡出；最终不看字幕完整试听，人物需要猜词或回放时继续降低 BGM 并重新输出。

没有匹配音乐时，把无 BGM 版本复制为 `07_交付/<项目名>_final_无BGM.mp4`，它是有效交付，不要求用户继续操作。

### 可编辑草稿交付

本步骤是每次成片后的默认自动交付，不等待用户再次提出“上传云草稿”。按 [jianying-execution.md](references/jianying-execution.md) 的“可编辑草稿与手机续剪”执行：从最终时间线复制交付草稿，保留所有片段和轨道；有 BGM 时在剪映界面中放回同一音乐、入点、裁切、淡入淡出和人声退位区间。保存后把完整草稿和关联本地素材备份到 `<工作区>/可编辑作品/<项目名>_editable_<YYYYMMDD_HHMMSS>/`，随后直接在剪映专业版中触发“上传到云空间/云草稿”，等待进度完成并确认桌面端显示同步成功。工作区目录是本地可恢复备份，手机版打开的是云空间草稿；不得把“已复制到工作区”报告成“手机已可打开”。

若云空间未登录、容量不足、网络失败或素材/效果不支持跨端，同样交付成片和本地可编辑草稿，但明确报告“手机云同步待完成”，不能声称手机续剪已经就绪。

只有剪映要求扫码登录、账号安全验证、付费扩容或其他必须由账号持有人确认的操作时，才请求用户介入一次；完成后立即继续上传，不重新询问剪辑选择。

完整播放最终交付文件，只问：

1. 不看计划能否看懂故事？
2. 哪里本能地想划走或觉得拖？
3. 哪里时间、地点、动作或音画明显断裂？
4. 人物是否轻松听清，音乐是否自然让位？
5. 结尾是否兑现开头，并在电视关机后出现固定彩色“晚安”结束卡？
6. 除固定片尾外，新增特效或音效是否自然，关闭后是否反而更好？

发现问题就直接修改并重新导出，不建立面向用户的分数验收。最后运行：

```bash
python3 <SKILL_DIR>/scripts/verify-export.py --video-path <最终成片> --target-seconds <目标秒数> --expected-width <宽> --expected-height <高> --expected-fps 30
```

文件检查只确认可播放、时长、画幅和音视频流，不替代完整审片。

## 硬阻塞

只在以下情况暂停并一次说清动作：

- 素材路径不存在或文件不可读。
- 计划拍摄模式中，不可替代故事段完全缺失。
- `ffmpeg`/`ffprobe` 缺失且当前阶段依赖它们。
- 剪映无法启动、保存或导出。
- 系统权限拒绝或磁盘空间不足。

librosa 缺失、曲库为空、普通素材不完美、景别/角度不同、没有指定音乐或非关键镜头缺失都不是硬阻塞。
